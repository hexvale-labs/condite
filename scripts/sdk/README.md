# SDK development

Prerequisites: Rust, Node 22+, a C toolchain, `wasm32-unknown-unknown`, and wasm-bindgen CLI matching Cargo.lock (currently 0.2.129).

```sh
just install sdk # Bun/Rust dependencies, WASM target, matching wasm-bindgen CLI
just check tools sdk
bun x --no-install playwright install --with-deps chromium
just build sdk
bun run check:consumer
bun run lint:sdk
bun run test:sdk
just check rust
just check wasm
```

On headless Linux the Electron main-process test uses `xvfb-run`; Electron also needs GTK 3 runtime libraries. Set `WASM_BINDGEN` to an alternate CLI path if needed. Development builds reuse the root `target/` directory and Cargo dev profile. Use `bun run build:sdk:release` for the size-optimized SDK profile and production size measurements. `CARGO_TARGET_DIR` is respected; core's release configuration is unchanged.

Builds produce `crates/condite-sdk-{node,wasm}/dist` packages. Release builds also produce `target/sdk-sizes.json` with raw addon, WASM, gzip WASM, glue, and minimal Rust-example sizes. The checked-in measurement snapshot is [docs/sdk-sizes.json](../../docs/sdk-sizes.json). These depend on platform and toolchain; they are measurements, not a cross-platform size guarantee. Generation runs ts-rs from shared wire types and supplements it with the public class signatures. TypeScript checks exercise both packages.

The runtime suite loads the actual addon in Node and Electron and the compiled WASM in Chromium, using local HTTP fixtures for the user-facing API surface, upload flow, sharing, retention, bigint precision, and partial failures. Core integration tests also run the Rust SDK against the actual server router. The independent `examples/sdk-consumer` project checks embedding outside this workspace. All SDK/shared/wrapper crates are MIT; condite-core retains AGPL-3.0-or-later.

From this directory, use `just install`, `just build`, or `just check tools`. Installation
fetches the whole Rust workspace plus the independent SDK consumer. Build regenerates
shared declarations before packaging; existing Bun build scripts retain their stale-type check.

## Privacy qualification

`test:sdk` exercises metadata cleaning, filename replacement and age roundtrips
with the actual Node/Electron/browser packages, plus worker-orchestration tests.
Synthetic Office/PDF/PNG fixtures are generated by `fixtures/generate.py`;
`fixtures/privacy.json` is checked in. Privacy package details are in
[condite-metadata](../../crates/condite-metadata/README.md).

Optional media requires explicitly installed FFmpeg/ffprobe and browser modules:

```sh
CONDITE_TEST_FFMPEG=/example/ffmpeg CONDITE_TEST_FFPROBE=/example/ffprobe \
  cargo test -p condite-metadata media::tests -- --include-ignored
CONDITE_FFMPEG_BROWSER_MODULES=/example/node_modules \
  CONDITE_TEST_FFMPEG=/example/ffmpeg CONDITE_TEST_FFPROBE=/example/ffprobe \
  node scripts/sdk/media-browser.mjs
```

The browser qualification uses `@ffmpeg/ffmpeg` 0.12.15 and `@ffmpeg/core` 0.12.10,
seven synthetic fixtures and independent native decoding. No binaries are
downloaded by these commands. See [browser setup](../../crates/condite-sdk-wasm/README.md)
for the explicit legacy-core compatibility options. Desktop Vencord installation
and its separate upstream checks are in [its README](../../clients/vencord/README.md).
